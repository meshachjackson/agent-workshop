# Contributing

Thanks for helping. This project is MIT licensed.

## Report a bug or ask for a feature

Open a GitHub Issue. For a bug, say what you did, what you expected, and what
happened. Security problems go through a private advisory, not an issue. See
`SECURITY.md`.

## Send a change

1. Open an issue first for anything bigger than a small fix.
2. Fork the repository and make a branch.
3. Keep the change small and focused. Add or update tests when you can.
4. Open a pull request that says what changed and why.

## Commit messages

Use short, plain messages. Conventional prefixes help (`fix:`, `feat:`, `docs:`).

## Keep it general

This project is a shared tool. Do not add personal data, real account names,
internal URLs or keys to code, tests, issues or commits. Put your own settings
in environment variables or an `instance/` folder that your fork keeps.
